Le cours en 6 phrases

  1. Le relationnel (SQL) est fiable grâce à ACID, mais son schéma est rigide, ses jointures coûtent cher et il se répartit mal sur plusieurs serveurs.
  2. Le volume, la vélocité et la variété des données (les 3V) ont rendu ces limites gênantes : d'où le NoSQL, « Not Only SQL ».
  3. Le NoSQL gagne en flexibilité (sans schéma), en scalabilité horizontale (sharding, réplication) et en vitesse (pas de jointures, données imbriquées).
  4. Sur plusieurs serveurs, le théorème CAP oblige à choisir, en cas de coupure réseau, entre cohérence et disponibilité. Le modèle BASE choisit la disponibilité.
  5. MongoDB est un NoSQL orienté documents : base, collections, documents, champs, en JSON/BSON.
  6. On l'interroge avec find(filtre, projection) puis sort, skip, limit, avec des opérateurs dédiés pour les sous-documents et les tableaux.

Chapitre 1 : pourquoi NoSQL

La chaîne logique du chapitre

Tout le chapitre est une suite de causes et de conséquences. Si vous retenez cette chaîne, vous retrouvez le reste.

3V : volume, vélocité, variété→ limites de SQL : schéma fixe, jointures, scale-up→ NoSQL : sans schéma, scale-out, sans jointures→ données réparties sur plusieurs serveurs→ CAP : choisir C ou A en cas de partition
choix C (CP)→modèle ACID, relationnel | choix A (AP)→modèle BASE, cohérence éventuelle, beaucoup de NoSQL

À savoir absolument

  • IndispensableDéfinition : NoSQL = Not Only SQL, bases non relationnelles pour données massives, variées ou semi-structurées.
  • Indispensable3V : Volume, Vélocité, Variété, chacun avec un exemple.
  • IndispensableACID : Atomicité (tout ou rien), Cohérence (état valide), Isolation (transactions parallèles sans interférence), Durabilité (permanent après commit).
  • IndispensableCAP : Cohérence, Disponibilité (Availability), Tolérance au Partitionnement. Impossible d'avoir les trois à la fois.
  • IndispensableBASE : Basically Available, Soft-state, Eventually consistent.
  • ImportantScale-up (une machine plus puissante) contre scale-out (plusieurs machines).
  • ImportantExemples : ACID pour PostgreSQL, MySQL, Oracle. BASE pour Cassandra, DynamoDB, MongoDB.
  • ImportantHôtel d'Agadir : CP, Rome refuse la réservation. AP, les deux serveurs acceptent puis on corrige.
  • ImportantLes 4 familles NoSQL : clé-valeur, documents, colonnes, graphes (schéma du cours).

À savoir absolument

  • IndispensableMongoDB : SGBD NoSQL orienté documents, JSON/BSON, nom venant de « humongous ».
  • IndispensableUn document a un _id unique et obligatoire (ObjectId généré si absent), taille maximale 16 Mo.
  • IndispensableUne collection n'impose pas de schéma : deux documents peuvent avoir des champs différents.
  • Indispensableuse MaBase ne crée pas la base, elle apparaît à la première insertion. La collection se crée toute seule à la première insertion.
  • IndispensableinsertOne renvoie acknowledged et insertedId. insertMany prend un tableau et renvoie insertedIds.
  • ImportantMoteur de stockage WiredTiger : cache en RAM, journal, compression.
  • ImportantCompass : interface graphique. mongosh : shell en ligne de commande. mongod : le processus serveur. URI par défaut : mongodb://localhost:27017.
  • ImportantcreateCollection avec capped: true exige size (octets). max est optionnel.
  • ImportantBases système : admin, local, config. Community (SSPL, gratuit) contre Enterprise (payant, support).
  • ImportantHistorique : 2009 version 1.0, 2014-2015 WiredTiger (3.0), 2018 transactions ACID (4.0).

Chapitre 3 : interroger avec find()

La formule à connaître

db.collection.find( filtre , projection ).sort( {...} ).skip( n ).limit( n )
filtre : quels documents ?→ tri→ skip→ limit→ projection : quels champs afficher ?

MongoDB applique le tri, puis skip, puis limit, quel que soit l'ordre d'écriture. Le résultat de find() est un curseur.

Les 12 phrases à connaître par cœur

  1. NoSQL veut dire Not Only SQL.
  2. Les 3V : Volume, Vélocité, Variété.
  3. Scale-up : une machine plus puissante. Scale-out : plusieurs machines.
  4. ACID : Atomicité, Cohérence, Isolation, Durabilité.
  5. CAP : Cohérence, Disponibilité, Partition. En cas de partition, on sacrifie C ou A.
  6. BASE : Basically Available, Soft-state, Eventually consistent.
  7. Base, Collections, Documents, Champs : l'équivalent de Base, Tables, Lignes, Colonnes.
  8. Un document : JSON/BSON, _id obligatoire, 16 Mo au maximum.
  9. Replica set : copies, disponibilité. Sharding : morceaux, volume.
  10. use ne crée rien tant qu'on n'insère pas.
  11. Plusieurs conditions dans un filtre : ET. Intervalle : $gte et $lte dans le même objet.
  12. $in : au moins une valeur. $all : toutes. $size : exactement N. $elemMatch : le même élément.
