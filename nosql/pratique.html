Partie 1 : questions de cours (5 points)

1.1 (1 pt) Donnez les 3V du Big Data et un exemple pour chacun.

Réponse

Volume : des pétaoctets de données par jour (Facebook). Vélocité : données produites et traitées en continu (capteurs IoT, transactions bancaires). Variété : tables, JSON/XML, images et vidéos.

1.2 (1 pt) Que dit le théorème CAP ? Qu'est-ce qu'un système CP ?

Réponse

Un système distribué ne peut pas garantir en même temps cohérence, disponibilité et tolérance au partitionnement. En cas de partition, il choisit la cohérence ou la disponibilité. Un système CP garde la cohérence et la tolérance au partitionnement et sacrifie la disponibilité : il peut refuser ou retarder des requêtes pour ne pas renvoyer de données incohérentes.

1.3 (1 pt) Comparez ACID et BASE en trois critères.

Réponse

Priorité : ACID privilégie la cohérence, BASE la disponibilité. Évolutivité : ACID verticale, BASE horizontale. Cohérence : stricte et immédiate en ACID, éventuelle en BASE. Exemples : PostgreSQL, MySQL, Oracle contre Cassandra, DynamoDB, MongoDB.

1.4 (1 pt) Donnez la correspondance entre les termes SQL et MongoDB.

Réponse

Base de données = base de données ; table = collection ; ligne = document ; colonne = champ.

1.5 (1 pt) Que fait use Entreprise si la base n'existe pas ? Quelle propriété de _id faut-il connaître ?

Réponse

Elle sélectionne la base sans la créer vraiment ; elle n'existe qu'après la première insertion. Le champ _id est obligatoire et unique : MongoDB génère un ObjectId si on n'en donne pas.

Partie 2 : création et insertion (4 points)

2.1 (1 pt) Créez explicitement une collection capped Journal de 1 Mo maximum et 500 documents maximum.

Solution
db.createCollection("Journal", { capped: true, size: 1048576, max: 500 })

1 Mo = 1 048 576 octets. size est obligatoire avec capped.

2.2 (1 pt) Insérez un employé « Salma », développeuse à Tanger, avec le salaire 11000 et les compétences JS et PHP.

Solution
db.Employes.insertOne({
  nom: "Salma", poste: "Développeur", salaire: 11000,
  adresse: { ville: "Tanger" }, competences: ["JS", "PHP"]
})

Pas de problème si on n'a pas d'_id ni de code postal : MongoDB crée l'_id, et le sous-document peut avoir moins de champs.

2.3 (2 pts) Insérez en une seule commande deux projets : le premier avec titre, année et membres (tableau) ; le second avec en plus un encadrant (objet avec nom et email).

Solution
db.Projets.insertMany([
  { titre: "Site e-commerce", annee: 2025, membres: ["Karim", "Leila"] },
  { titre: "Application mobile", annee: 2026, membres: ["Mehdi"],
    encadrant: { nom: "Dr. Alaoui", email: "alaoui@exemple.ma" } }
])

Une seule commande pour plusieurs documents : insertMany avec un tableau entre crochets.

Partie 3 : requêtes sur Employes (8 points)

Écrivez la requête et donnez le résultat attendu (les _id suffisent).

3.1 Les développeurs d'Agadir.

Solution
db.Employes.find({ poste: "Développeur", "adresse.ville": "Agadir" })

Résultat : _id 1 (Karim) et 3 (Mehdi). Youssef est à Agadir mais stagiaire.

3.2 Les employés dont le salaire est entre 10000 et 14000 inclus.

Solution
db.Employes.find({ salaire: { $gte: 10000, $lte: 14000 } })

Résultat : _id 1 (12000), 2 (14000), 3 (10000). Youssef n'a pas de salaire, donc il est exclu. Nora (18000) aussi.

3.3 Les employés qui maîtrisent à la fois SQL et JS.

Solution
db.Employes.find({ competences: { $all: ["SQL", "JS"] } })

Résultat : _id 1 (Karim) et 4 (Nora). Leila a SQL mais pas JS, Mehdi a JS mais pas SQL.

3.4 Les employés qui connaissent Java ou Python.

Solution
db.Employes.find({ competences: { $in: ["Java", "Python"] } })

Résultat : _id 1 (Python), 2 (Python), 3 (Java).

3.5 Les employés qui ont exactement 4 compétences.

Solution
db.Employes.find({ competences: { $size: 4 } })

Résultat : _id 4 (Nora).

3.6 Les employés sans champ salaire. Puis ceux dont la liste de compétences est vide.

Solution
db.Employes.find({ salaire: { $exists: false } })   // _id 5
db.Employes.find({ competences: { $size: 0 } })     // _id 5

3.7 Les deux employés les mieux payés, nom et salaire uniquement.

Solution
db.Employes.find({}, { nom: 1, salaire: 1, _id: 0 }).sort({ salaire: -1 }).limit(2)

Résultat : Nora 18000, Leila 14000. Un champ absent compte comme null, plus petit qu'un nombre, donc Youssef serait en dernier en tri décroissant et premier en tri croissant.

3.8 Les employés dont le nom commence par K ou L ; leur nombre.

Solution
db.Employes.find({ nom: /^[KL]/ })
db.Employes.countDocuments({ nom: /^[KL]/ })

Résultat : Karim et Leila, donc 2.

3.9 Le nom et la ville de tous les employés d'Agadir, triés par nom décroissant.

Solution
db.Employes.find({ "adresse.ville": "Agadir" }, { nom: 1, "adresse.ville": 1, _id: 0 }).sort({ nom: -1 })

Résultat : Youssef, Mehdi, Karim, chacun avec adresse: { ville: "Agadir" }.

3.10 Vérifiez que tous les salaires présents sont de type numérique.

Solution
db.Employes.find({ salaire: { $exists: true, $type: "number" } })   // _id 1, 2, 3, 4
db.Employes.find({ salaire: { $exists: true, $not: { $type: "number" } } })   // aucun résultat attendu

Partie 4 : lire et corriger des requêtes (3 points)

4.1 Que renvoie db.Employes.find({ competences: { $size: 2 } }) ?

Solution

Les employés qui ont exactement deux compétences : Leila (Python, SQL) et Mehdi (JS, Java).

4.2 Que renvoie db.Employes.find({ competences: ["SQL", "JS"] }) ? Est-ce la même chose que la question 3.3 ?

Solution

Aucun document. Passer un tableau comme valeur teste l'égalité exacte du tableau, avec le même ordre et sans autre élément. Karim a ["JS", "Python", "SQL"], Nora a quatre éléments. Ce n'est pas la même chose que $all, qui accepte d'autres éléments et ne demande pas d'ordre.

4.3 Trouvez l'erreur dans chacune de ces trois requêtes :

a) db.Employes.find({ adresse.ville: "Agadir" })
b) db.Employes.find({ poste: "Développeur" }, { nom: 1, salaire: 0 })
c) db.Employes.find({ $or: { poste: "Stagiaire", salaire: 10000 } })
Solution
  • a) La notation pointée doit être entre guillemets : "adresse.ville".
  • b) On ne mélange pas inclusion (nom: 1) et exclusion (salaire: 0). Garder { nom: 1 } seul, ou exclure seulement.
  • c) $or attend un tableau : { $or: [ { poste: "Stagiaire" }, { salaire: 10000 } ] }.

4.4 Que renvoie db.Employes.find({ salaire: null }) ?

Solution

Youssef (_id 5) : null correspond aussi aux champs absents. Personne n'a salaire explicitement à null, mais le champ manque chez lui.

Correction rapide : points à vérifier avant de rendre

  • Toutes les clés avec un point sont entre guillemets.
  • Pas de mélange 1 et 0 dans la projection, et _id: 0 si on ne veut pas l'_id.
  • $or, $and, $in, $all reçoivent un tableau.
  • Bornes inclusives : $gte et $lte.
  • Tableau d'objets avec deux conditions : $elemMatch.
  • sort avant limit dans votre tête.
