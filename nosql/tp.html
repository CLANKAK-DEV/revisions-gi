Avant de commencer : ce que je suppose

Dans le PDF du TP3, certains symboles de comparaison ont disparu à l'extraction du texte (par exemple « moyenne 15 »). Je lis ces questions comme « inférieure ou égale à 15 », « note supérieure ou égale à 17 », « moyenne supérieure ou égale à 16 ». Vérifiez avec l'énoncé papier si besoin. Quand une question est ambiguë, je donne les deux lectures.

TP2 : Introduction à MongoDB

Installation, en résumé

  1. Télécharger MongoDB Community Server (MSI pour Windows) sur le site officiel, type d'installation « Complete », services par défaut, cocher l'installation de Compass.
  2. Télécharger et installer MongoDB Shell (mongosh) à part.
  3. Vérifier dans un terminal : mongosh --version. (Le TP écrit mongod --version pour le serveur.)

Exercice 1 : base Genie_Informatique_MongoDB avec Compass

Tout se fait dans Compass : on colle du JSON dans la fenêtre Insert Document (vue JSON).

1 et 2. Connexion, création de la base et de la collection Etudiants

Solution
  1. Ouvrir Compass. L'URI par défaut est mongodb://localhost:27017. Cliquer sur Connect.
  2. Cliquer sur Create Database. Database Name : Genie_Informatique_MongoDB. Collection Name : Etudiants. Create Database.

3. Un premier document simple (id, nom, ville)

Solution

Ouvrir la collection Etudiants, Add Data, Insert Document, coller puis Insert :

{ "id": 1, "nom": "Omar", "ville": "Agadir" }

4. Au moins 3 étudiants avec des informations variées

Solution

Dans Insert Document on peut coller un tableau de documents :

[
  { "id": 2, "nom": "Sara", "ville": "Rabat", "filiere": "Informatique" },
  { "id": 3, "nom": "Amine", "ville": "Marrakech", "age": 24 },
  { "id": 4, "nom": "Aya", "ville": "Fès", "email": "aya@exemple.ma" }
]

Chaque document a des champs différents : c'est volontaire, pour montrer la flexibilité.

Solution
{ "code": "BD1", "intitule": "Bases de données", "semestre": "S7" }

{ "code": "NS1", "intitule": "NoSQL", "semestre": "S7",
  "enseignant": { "nom": "Dr. Alaoui", "email": "alaoui@exemple.ma" } }

Solution
{ "etudiant_id": 1, "notes": [15, 12, 18] }

{ "etudiant_id": 2,
  "resultats": [
    { "matiere": "BD", "note": 16 },
    { "matiere": "Réseaux", "note": 14 }
  ] }

Premier cas : tableau de valeurs simples. Second cas : tableau de sous-documents.

  "emails": ["hiba@exemple.ma", "hiba.perso@exemple.com"] }

Solution

Exercice 2 : CinemaDB avec mongosh

1 à 3. Base, collection Films, document simple

Solution
use CinemaDB
db.createCollection("Films")
db.Films.insertOne({ id: 1, titre: "Inception", annee: 2010 })

Résultat attendu : { acknowledged: true, insertedId: ObjectId("...") }. Le champ id n'est pas l'_id : MongoDB crée quand même son propre _id.

4 et 5. Document intermédiaire (genre, duree), puis document avancé (réalisateur imbriqué, tableau d'acteurs)

Solution
db.Films.insertOne({ id: 2, titre: "Titanic", annee: 1997, genre: "Drame", duree: 195 })

db.Films.insertOne({
  id: 3, titre: "Interstellar", annee: 2014, genre: "Science-fiction", duree: 169,
  realisateur: { nom: "Christopher Nolan", nationalite: "UK" },
  acteurs: ["Matthew McConaughey", "Anne Hathaway"]
})

6. Montrer la flexibilité : mêmes Films, champs différents (langue, budget, noteIMDB)

Solution
db.Films.insertOne({ id: 4, titre: "Amélie", annee: 2001, langue: "Français", budget: 10000000, noteIMDB: 8.3 })

Dans la même collection coexistent maintenant quatre formes de documents. Aucun ALTER TABLE n'a été nécessaire.

// simples
db.Realisateurs.insertMany([

Solution
db.Seances.insertMany([

TP3 : La récupération des documents

Mise en place

use TP3
db.EtudiantsTP.insertMany([ ...D1... ])
db.EtudiantsTP2.insertMany([ ...D2... ])
db.EtudiantsTP3.insertMany([ ...D3... ])

Piège dans l'énoncé

Dans D3, le premier document (Omar) est écrit avec id: 1 et non _id: 1. MongoDB lui crée donc un _id de type ObjectId, alors que les deux autres ont _id: 2 et _id: 3. Ça ne change pas les résultats des requêtes, mais ça se voit à l'affichage.

Partie 1 : EtudiantsTP (documents simples)

Données : Omar 22 ans Informatique Agadir 15 / Sara 21 Mathématiques Rabat 17 / Yassine 23 Physique Casablanca 14 / Amine 24 Informatique Marrakech 18 / Aya 22 Chimie Fès 13 / Hiba 25 Mathématiques Agadir 19.

1 et 2. Tous les étudiants, puis nom et filière seulement

Solution
db.EtudiantsTP.find()
db.EtudiantsTP.find({}, { nom: 1, filiere: 1, _id: 0 })

Le filtre est vide {} parce qu'on veut tous les documents, la projection vient en 2e argument.

3. Filière Informatique

Solution
db.EtudiantsTP.find({ filiere: "Informatique" })

Résultat : Omar et Amine.

4 et 5. Moyenne > 15, puis moyenne ≤ 15

Solution
db.EtudiantsTP.find({ moyenne: { $gt: 15 } })    // Sara 17, Amine 18, Hiba 19
db.EtudiantsTP.find({ moyenne: { $lte: 15 } })   // Omar 15, Yassine 14, Aya 13

Si l'énoncé voulait « ≥ 15 », on écrit $gte et Omar rejoint Sara, Amine, Hiba. Omar (15) est le cas limite à surveiller.

6. Ville Agadir

Solution
db.EtudiantsTP.find({ ville: "Agadir" })   // Omar, Hiba

7 et 8. Tri par nom croissant, tri par moyenne décroissante

Solution
db.EtudiantsTP.find().sort({ nom: 1 })
// Amine, Aya, Hiba, Omar, Sara, Yassine

db.EtudiantsTP.find().sort({ moyenne: -1 })
// Hiba 19, Amine 18, Sara 17, Omar 15, Yassine 14, Aya 13

9 et 10. Les 3 premiers, puis le nombre total

Solution
db.EtudiantsTP.find().limit(3)       // Omar, Sara, Yassine (ordre d'insertion, non garanti)
db.EtudiantsTP.countDocuments()      // 6

« Les 3 premiers » sans tri n'a pas d'ordre garanti. En pratique on voit l'ordre d'insertion, mais pour un résultat sûr il faut un sort().

Partie 2 : EtudiantsTP2 (documents imbriqués)

Données : Omar (info: age 22, ville Agadir), Informatique, 15 / Sara (21, Rabat), Mathématiques, 17 / Amine (24, Marrakech), Informatique, 18.

1 à 4. Tous, nom et filière, nom et ville imbriquée, filière Informatique

Solution
db.EtudiantsTP2.find()
db.EtudiantsTP2.find({}, { nom: 1, filiere: 1, _id: 0 })
db.EtudiantsTP2.find({}, { nom: 1, "info.ville": 1, _id: 0 })
db.EtudiantsTP2.find({ filiere: "Informatique" })    // Omar, Amine

Le résultat de la 3e : { nom: "Omar", info: { ville: "Agadir" } }. La ville reste dans son sous-document.

5 et 6. Ville Agadir, puis âge supérieur à 21

Solution
db.EtudiantsTP2.find({ "info.ville": "Agadir" })   // Omar
db.EtudiantsTP2.find({ "info.age": { $gt: 21 } })  // Omar (22), Amine (24)

Sara a exactement 21 ans, donc elle est exclue par $gt.

7. Moyenne comprise entre 15 et 18 inclus

Solution
db.EtudiantsTP2.find({ moyenne: { $gte: 15, $lte: 18 } })   // les 3 : 15, 17, 18

8. Nom et moyenne seulement, triés par moyenne décroissante

Solution
db.EtudiantsTP2.find({}, { nom: 1, moyenne: 1, _id: 0 }).sort({ moyenne: -1 })
// Amine 18, Sara 17, Omar 15

On peut trier sur un champ qu'on ne projette pas ; ici on le projette pour voir le tri.

9. Ville qui contient la lettre « a » ($regex sur info.ville)

Solution
db.EtudiantsTP2.find({ "info.ville": { $regex: "a" } })
// ou : db.EtudiantsTP2.find({ "info.ville": /a/ })

Agadir, Rabat et Marrakech contiennent tous un « a » minuscule : les 3 documents sortent. Sans l'option i, la casse compte : « A » majuscule ne compterait pas. Ajoutez $options: "i" ou /a/i pour ignorer la casse.

10. Vérifier que info.age existe et est numérique

Solution
db.EtudiantsTP2.find({ "info.age": { $exists: true, $type: "number" } })

Les 3 documents sortent. Pour détecter les anomalies, comparez avec countDocuments() : si les deux nombres sont égaux, tous les âges sont numériques.

Partie 3 : EtudiantsTP3 (tableaux d'objets)

Données : Omar, Informatique, résultats [Programmation 16, BD 18, Réseaux 14] / Sara, Mathématiques, [Analyse 17, Algèbre 15] / Yassine, Physique, [Électricité 13, Mécanique 16].

1. Étudiants ayant un module « BD »

Solution
db.EtudiantsTP3.find({ "resultats.module": "BD" })   // Omar

MongoDB parcourt le tableau et regarde le champ module de chaque élément.

2. Au moins un module avec une note > 15

Solution
db.EtudiantsTP3.find({ "resultats.note": { $gt: 15 } })

Omar (16, 18), Sara (17) et Yassine (16) : les trois documents. Aucun filtre complexe n'est nécessaire car il n'y a qu'une seule condition.

3. Étudiants dont les modules sont Programmation et Réseaux ($all)

Solution
db.EtudiantsTP3.find({ "resultats.module": { $all: ["Programmation", "Réseaux"] } })   // Omar

$all veut dire « contient les deux », pas « n'a que ces deux ». Omar a aussi BD et il est quand même retenu.

4. Au moins 3 modules ($size: 3)

Solution
db.EtudiantsTP3.find({ resultats: { $size: 3 } })   // Omar

$size teste « exactement 3 ». Ici personne n'a plus de 3 modules, donc ça revient au même que « au moins 3 ». Si un étudiant avait 4 modules, il ne sortirait pas.

Pour un vrai « au moins 3 » : db.EtudiantsTP3.find({ "resultats.2": { $exists: true } }) (le troisième élément existe).

5. Note ≥ 17 dans « BD » ($elemMatch)

Solution
db.EtudiantsTP3.find({ resultats: { $elemMatch: { module: "BD", note: { $gte: 17 } } } })   // Omar (BD = 18)

$elemMatch garantit que module = BD et note ≥ 17 portent sur le même élément du tableau.

6 et 7. Informatique triés par nom, puis nom et modules seulement

Solution
db.EtudiantsTP3.find({ filiere: "Informatique" }).sort({ nom: 1 })   // Omar

db.EtudiantsTP3.find({}, { nom: 1, "resultats.module": 1, _id: 0 })
// { nom: "Omar", resultats: [ { module: "Programmation" }, { module: "BD" }, { module: "Réseaux" } ] } ...

La projection "resultats.module": 1 garde seulement le champ module de chaque élément du tableau.

8. Une note comprise entre 14 et 18 dans un module

Solution
db.EtudiantsTP3.find({ resultats: { $elemMatch: { note: { $gte: 14, $lte: 18 } } } })

Les trois étudiants sortent (Omar 16, Sara 17, Yassine 16). Utilisez $elemMatch pour que les deux bornes visent la même note. Sans lui, { "resultats.note": { $gte: 14, $lte: 18 } } peut être satisfait par une note ≥ 14 et une autre ≤ 18.

9. Compter les étudiants ayant une note moyenne ≥ 16

Solution

La collection EtudiantsTP3 n'a pas de champ moyenne : la question est ambiguë. Deux lectures possibles.

Lecture A : la moyenne des notes de chaque étudiant est ≥ 16. Il faut calculer la moyenne, avec $expr et $avg (hors programme du cours, mais c'est la seule façon propre) :

db.EtudiantsTP3.countDocuments({ $expr: { $gte: [ { $avg: "$resultats.note" }, 16 ] } })
// Omar : (16+18+14)/3 = 16   Sara : (17+15)/2 = 16   Yassine : 14,5  => 2

Lecture B : l'étudiant a au moins une note ≥ 16 (version simple, compatible avec le cours) :

db.EtudiantsTP3.countDocuments({ "resultats.note": { $gte: 16 } })   // 3

À l'examen, si une question est ambiguë, écrivez votre interprétation en une phrase avant la requête.

10. Vérifier que resultats existe et est un tableau

Solution
db.EtudiantsTP3.find({ resultats: { $exists: true, $type: "array" } })   // les 3

Partie 4 : la collection movies

A) Mise en place

Solution
  1. Télécharger movies.json (jeu d'exemple sample_mflix).
  2. Installer MongoDB Database Tools, ajouter C:\Program Files\MongoDB\Tools\100\bin à la variable d'environnement Path, rouvrir le terminal, vérifier avec mongoimport --version.
  3. Importer, depuis un terminal ordinaire (pas dans mongosh) :
mongoimport --host localhost:27017 --db TP_Movies --collection movies --file "C:\chemin\vers\movies.json"
  1. Vérifier : mongosh, puis use TP_Movies, puis db.movies.countDocuments().

B) Les 16 questions

Solution
use TP_Movies

// 1
db.movies.find()
// 2
db.movies.find({}, { title: 1, year: 1, _id: 0 })
// 3
db.movies.find({ year: 1990 })
// 4
db.movies.find({ runtime: { $gt: 120 } })
// 5
db.movies.find({ "imdb.rating": { $gte: 8 } })
// 6
db.movies.find().sort({ year: 1 })
// 7
db.movies.find({ "imdb.rating": { $type: "number" } }).sort({ "imdb.rating": -1 })
// 8
db.movies.find().limit(5)
// 9
db.movies.find({}, { title: 1, year: 1, _id: 0 }).sort({ year: 1 })
// 10
db.movies.countDocuments()
// 11
db.movies.find({ "imdb.rating": { $gte: 7, $lte: 9 } })
// 12
db.movies.find({ genres: "Drama" })
// 13
db.movies.find({ title: { $regex: "Love" } })
// 14
db.movies.find({ "imdb.rating": { $exists: true } })
// 15
db.movies.find({ year: { $type: "number" } })
// 16
db.movies.find({ genres: { $all: ["Comedy", "Romance"] } })

Explications utiles

  • Questions 5, 7, 11, 14 : le champ est imbriqué, donc notation pointée entre guillemets.
  • Question 7 : j'ajoute le filtre $type: "number". Le tri MongoDB range les types dans un ordre fixe (nombres avant chaînes). Dans ce jeu de données certains films peuvent avoir une note vide en texte : en tri décroissant ils remonteraient en tête. À vérifier avec db.movies.countDocuments({ "imdb.rating": { $type: "string" } }).
  • Question 12 : genres est un tableau, et { genres: "Drama" } teste si le tableau contient Drama.
  • Question 13 : pour ignorer la casse, /love/i.
  • Question 14 : $exists: true accepte aussi un champ à null. Pour exclure les null, ajoutez $type: "number".
  • Question 15 : le but est de détecter les films dont year n'est pas un nombre. Pour les trouver : db.movies.find({ year: { $not: { $type: "number" } } }).
  • Question 16 : $all, donc les deux genres, et d'autres genres sont permis en plus.

Exercices inspirés des TP

Exercice A : la bibliothèque (find, projection, tri, tableaux)

Insérez ces données dans une base Bibliotheque :

db.Livres.insertMany([
  { _id: 1, titre: "Le Petit Prince", auteur: "Saint-Exupéry", annee: 1943, genres: ["Conte", "Philosophie"], prix: 60, stock: 12 },
  { _id: 2, titre: "L'Etranger", auteur: "Camus", annee: 1942, genres: ["Roman", "Philosophie"], prix: 45, stock: 0 },
  { _id: 3, titre: "Les Misérables", auteur: "Hugo", annee: 1862, genres: ["Roman", "Histoire"], prix: 90, stock: 5 },
  { _id: 4, titre: "La Peste", auteur: "Camus", annee: 1947, genres: ["Roman", "Philosophie"], prix: 55 },
  { _id: 5, titre: "Notre-Dame de Paris", auteur: "Hugo", annee: 1831, genres: ["Roman", "Histoire"], prix: 70, stock: 8 },
  { _id: 6, titre: "Antigone", auteur: "Anouilh", annee: 1944, genres: ["Théâtre"], prix: 35, stock: 3 }
])

A1. Les titres des livres de Camus (sans l'_id)

Solution

Étape 1 : filtre sur l'auteur. Étape 2 : projection du titre seulement, avec _id: 0.

db.Livres.find({ auteur: "Camus" }, { titre: 1, _id: 0 })

Résultat : L'Etranger, La Peste.

A2. Les livres publiés après 1940 dont le prix est au plus 55

Solution

Deux conditions sur deux champs différents : ET implicite. Après 1940 : _id 1, 2, 4, 6. Prix ≤ 55 parmi eux : 2 (45), 4 (55), 6 (35).

db.Livres.find({ annee: { $gt: 1940 }, prix: { $lte: 55 } })

Résultat : L'Etranger, La Peste, Antigone.

A3. Les livres de Hugo OU de prix supérieur à 80

Solution
db.Livres.find({ $or: [ { auteur: "Hugo" }, { prix: { $gt: 80 } } ] })

Résultat : Les Misérables (Hugo et 90) et Notre-Dame de Paris (Hugo). Le livre à 90 est déjà un Hugo, donc il n'y a pas de doublon.

A4 et A5. Livres du genre Philosophie ; livres à la fois Roman et Histoire

Solution
db.Livres.find({ genres: "Philosophie" })                    // _id 1, 2, 4
db.Livres.find({ genres: { $all: ["Roman", "Histoire"] } })  // _id 3, 5

Pour un seul genre, la valeur seule suffit. Pour deux genres obligatoires en même temps : $all. Avec $in on aurait obtenu les livres qui sont Roman ou Histoire (4 livres).

A6. Titres commençant par « La » suivis d'un espace

Solution
db.Livres.find({ titre: /^La / })    // La Peste

Sans l'espace, /^La/ trouverait aussi un titre comme « Labyrinthe ». Ici le résultat est identique.

A7. Livres sans champ stock ; livres dont le stock vaut 0 ; que renvoie { stock: null } ?

Solution
db.Livres.find({ stock: { $exists: false } })   // La Peste (_id 4)
db.Livres.find({ stock: 0 })                    // L'Etranger (_id 2)
db.Livres.find({ stock: null })                 // La Peste seulement

Zéro n'est pas null. { stock: null } ramène les champs absents ou égaux à null, donc La Peste, mais pas L'Etranger.

A8. Les deux livres les plus chers

Solution
db.Livres.find().sort({ prix: -1 }).limit(2)

Résultat : Les Misérables (90), Notre-Dame de Paris (70). Le tri doit venir avant la limite, mais MongoDB l'applique de toute façon dans cet ordre.

A9. Deuxième page de 2 livres, triés par titre croissant

Solution

Titres triés (ordre binaire) : Antigone, L'Etranger, La Peste, Le Petit Prince, Les Misérables, Notre-Dame de Paris. Page 1 = les 2 premiers, page 2 = les 2 suivants.

db.Livres.find().sort({ titre: 1 }).skip(2).limit(2)

Résultat : La Peste, Le Petit Prince.

A10 à A12. Compter les romans ; vérifier que prix est numérique ; compter la philosophie

Solution
db.Livres.countDocuments({ genres: "Roman" })         // 4
db.Livres.countDocuments({ prix: { $type: "number" } })  // 6, donc tous les prix sont numériques
db.Livres.countDocuments({ genres: "Philosophie" })    // 3

Exercice B : les commandes (tableaux de sous-documents)

db.Commandes.insertMany([
  { _id: 1, client: "Omar", ville: "Agadir",
    articles: [ { produit: "Clavier", qte: 2, prix: 150 }, { produit: "Souris", qte: 1, prix: 80 } ], statut: "livrée" },
  { _id: 2, client: "Sara", ville: "Rabat",
    articles: [ { produit: "Ecran", qte: 1, prix: 1200 } ], statut: "en cours" },
  { _id: 3, client: "Amine", ville: "Agadir",
    articles: [ { produit: "Clavier", qte: 5, prix: 140 }, { produit: "Ecran", qte: 2, prix: 1150 }, { produit: "Câble", qte: 10, prix: 20 } ], statut: "livrée" },
  { _id: 4, client: "Aya", ville: "Fès", articles: [], statut: "annulée" }
])

B1. Commandes qui contiennent un Clavier

Solution
db.Commandes.find({ "articles.produit": "Clavier" })   // _id 1 et 3

B2. Commandes avec un Clavier dont le prix est supérieur à 145

Solution

Il faut que « Clavier » et « prix > 145 » portent sur le même article : $elemMatch.

db.Commandes.find({ articles: { $elemMatch: { produit: "Clavier", prix: { $gt: 145 } } } })   // _id 1

Dans la commande 3, le clavier est à 140 : il ne passe pas.

Version fausse, très fréquente :

db.Commandes.find({ "articles.produit": "Clavier", "articles.prix": { $gt: 145 } })   // _id 1 ET 3 (erreur)

La commande 3 est renvoyée à tort : elle a un Clavier (premier article) et un article à plus de 145 (l'écran à 1150). Deux articles différents ont validé les deux conditions.

B3. Commandes avec exactement 3 articles ; commandes sans aucun article

Solution
db.Commandes.find({ articles: { $size: 3 } })   // _id 3
db.Commandes.find({ articles: { $size: 0 } })   // _id 4

B4. Les clients d'Agadir, triés par nom, nom seulement

Solution
db.Commandes.find({ ville: "Agadir" }, { client: 1, _id: 0 }).sort({ client: 1 })

Résultat : Amine, Omar.

B5. Commandes livrées ou annulées

Solution
db.Commandes.find({ statut: { $in: ["livrée", "annulée"] } })   // _id 1, 3, 4

Équivalent avec $or, mais $in est plus court quand c'est le même champ.

B6. Pour les commandes contenant un Ecran, afficher le client et seulement l'article Ecran

Solution
db.Commandes.find(
  { "articles.produit": "Ecran" },
  { client: 1, "articles.$": 1, _id: 0 }
)

Résultat : { client: "Sara", articles: [ { produit: "Ecran", qte: 1, prix: 1200 } ] } et { client: "Amine", articles: [ { produit: "Ecran", qte: 2, prix: 1150 } ] }. L'opérateur positionnel $ ne garde que l'élément du tableau qui a satisfait le filtre.

Les résultats de ces exercices ont été recalculés avec une bibliothèque qui reproduit le langage de requête MongoDB.
