Pièges et aide-mémoire

Les erreurs qui coûtent des points, puis une fiche à relire la veille de l'examen.

Erreurs fréquentes en théorie

1. Confondre les deux « A »

Le A de ACID est l'Atomicité. Le A de CAP est la Disponibilité (Availability). Écrivez toujours le mot en entier quand vous répondez.

2. Dire que CAP permet de choisir 2 propriétés sur 3 « librement »

La tolérance au partitionnement est imposée par la réalité d'un réseau. Le choix concret, en cas de coupure, est entre cohérence (CP) et disponibilité (AP).

3. Dire que NoSQL veut dire « pas de SQL »

Not Only SQL : non relationnel, mais pas anti-SQL.

4. Dire que MongoDB n'est jamais ACID

Le tableau ACID/BASE du cours range MongoDB côté BASE, mais MongoDB propose des transactions ACID multi-documents depuis la version 4.0 (2018). Citez les deux faits si la question est ouverte.

5. Confondre réplication et sharding

Réplication : mêmes données copiées sur plusieurs serveurs (disponibilité). Sharding : données découpées entre serveurs (volume).

6. Croire que use crée la base

Elle apparaît seulement après la première insertion (ou création de collection).

7. Oublier que la collection se crée toute seule

Pas besoin de createCollection avant un insertOne. Mais createCollection reste nécessaire pour les options (capped, validator).

8. Mélanger les vocabulaires

Collection, pas table. Document, pas ligne. Champ, pas colonne.

Pièges propres aux TP

  • TP3, D3 : Omar est écrit avec id: 1 (sans underscore), donc son _id est un ObjectId généré.
  • TP3, partie 3, question 3 : « dont tous les modules sont Programmation et Réseaux » avec $all veut dire « contient les deux », pas « n'a que ces deux ».
  • TP3, partie 3, question 9 : la moyenne n'existe pas comme champ ; expliquez votre interprétation.
  • TP3, partie 4 : mongoimport se tape dans un terminal normal, pas dans mongosh. Ajoutez le dossier des Database Tools au Path puis rouvrez le terminal.
  • TP2 : le JSON de Compass n'accepte pas les commentaires //.
  • Le fichier movies.json peut contenir des champs au mauvais type (année en texte, note vide). C'est le but des questions avec $type. En tri décroissant, les chaînes passent avant les nombres.

Méthode pour l'examen

  1. Lisez la question et soulignez : filtre, projection, tri, limite. Une requête find() se construit dans cet ordre.
  2. Repérez les champs imbriqués (point + guillemets) et les tableaux ($in, $all, $size, $elemMatch).
  3. Repérez les bornes : « supérieur à » = strict, « au moins » = inclusif.
  4. Écrivez la requête, puis simulez-la sur 2 documents de l'énoncé.
  5. Vérifiez les accolades, les crochets, les guillemets.
  6. Pour une question ambiguë, notez l'hypothèse en une phrase.

CAP  : Cohérence, Availability (disponibilité), Partition tolerance
BASE : Basically Available, Soft-state, Eventually consistent
