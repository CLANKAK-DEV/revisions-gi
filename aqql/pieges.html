Pièges et aide-mémoire

Les erreurs qui coûtent des points, y compris les incohérences repérées dans les slides, puis une méthode pour les calculs.

Pièges de cours

1. Erreur, défaut, défaillance

Ordre : erreur (humain), défaut (produit), défaillance (exploitation). Le bug est un mot vague. Un défaut est une erreur humaine non détectée.

2. Qualité du code, qualité du logiciel

La qualité ne se limite pas au code source : elle couvre aussi procédures, règles, documentation et données, et repose sur le produit et le processus.

3. Facteur, critère

Facteur : vision externe (utilisateur). Critère : vision interne (développeur). Ne pas inverser.

4. Les nombres des modèles

McCall : 11 facteurs et 23 critères. ISO 9126 : 6 et 27. ISO 25010:2011 : 8. ISO 25010:2023 : 9 caractéristiques et 38 sous-caractéristiques. La slide liste en fait 40 sous-caractéristiques : retenez 38, comme le texte.

5. Security et safety

Security : protection contre accès non autorisés (confidentialité, intégrité...). Safety : absence de risque pour les personnes, l'environnement, les biens (fail-safe...). Nouveauté de 2023.

6. Qualité interne, externe, à l'usage

Interne : sans exécuter le code. Externe : pendant l'exécution (tests). À l'usage : conditions réelles chez l'utilisateur.

7. Échelles de Stevens

Zéro arbitraire : intervalle (température en Celsius). Zéro absolu : ratio (taux de couverture). Comptage : absolu. Ordre sans écart mesurable : ordinal (sévérité d'un bug).

8. Complexité cyclomatique et cognitive

Cyclomatique : chemins linéairement indépendants (McCabe, 1976). Cognitive : effort pour comprendre (SonarSource, 2016).

Pièges de TD et TP

  • TD1 : le rapport tient sur une page. Il faut les quatre blocs (cas, chaîne causale, impacts, mesures SQA par phase du SDLC) et les références.
  • TD2 : définir en tête ce que vous appelez qualité mesurée et qualité totale, puisque le cours ne les définit pas explicitement.
  • TD3 : justifiez le comptage des tokens (par exemple les deux-points, les parenthèses, le commentaire ignoré).
  • TP CKJM : le tableau demande Ca et Ce, le fichier metrics.txt contient Ca et NPM. Ce se déduit des couplages sortants.
  • TP SonarQube : ne pas laisser <VOTRE_TOKEN_SONAR> dans sonar-project.properties. Compiler avant de scanner. Relancer l'analyse après correction pour comparer.
  • La slide sur Ca et Ce mélange entrant et sortant dans le texte. Suivez les exemples chiffrés : Forme (Ca = 2, Ce = 0) est la classe la plus stable.

Méthode pour les calculs

  1. Écrivez la formule avant de remplacer les valeurs.
  2. Pour McCabe : comptez π en listant chaque if, for, while, case ; vérifiez avec E - N + 2P si le graphe est donné.
  3. Pour Halstead : tableau des opérateurs avec leurs occurrences, tableau des opérandes, puis n1, n2, N1, N2, et vérifiez que la somme des occurrences correspond à N1 et N2.
  4. Pour un modèle pondéré : note de chaque métrique (regardez les crochets), critères, facteurs, qualité, pourcentage.
  5. Terminez par une phrase d'interprétation avec la norme du cours.
