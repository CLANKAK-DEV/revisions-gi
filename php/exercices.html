Chapitre 1 : introduction à PHP

Exercice 1.1 : questions de compréhension

Rôle du client et du serveur ; décomposer https://www.epa.ma:443/cours/php.php?chapitre=1 ; GET et POST ; deux sites dynamiques ; pourquoi on ne voit jamais le code PHP.

Solution
  1. Le client (le navigateur) prend l'initiative : il envoie une requête et affiche la réponse. Le serveur fonctionne en permanence, écoute sur un port (80 ou 443), traite les requêtes et renvoie une réponse.
  2. Protocole https:// ; domaine www.epa.ma ; port :443 ; chemin /cours/php.php ; paramètre ?chapitre=1.
  3. GET demande (lit) une ressource, les paramètres sont dans l'URL. POST envoie des données dans le corps de la requête, par exemple pour soumettre un formulaire.
  4. Un réseau social et une boutique en ligne : la page dépend de l'utilisateur connecté (fil d'actualité, panier), elle est construite au moment de la demande.
  5. Apache confie le fichier à l'interpréteur PHP, qui exécute le code et ne renvoie que le HTML produit. Le code PHP ne quitte jamais le serveur.

Exercice 1.2 : vrai ou faux

1. PHP est compilé et s'exécute dans le navigateur. 2. Un fichier PHP peut contenir du HTML. 3. Le typage est dynamique. 4. Un site statique peut afficher le nom de l'utilisateur connecté. 5. Laravel est un langage concurrent de PHP.

Solution
  1. Faux : PHP est interprété et s'exécute sur le serveur.
  2. Vrai : on mélange HTML et code entre <?php et ?>.
  3. Vrai : le type se déduit de la valeur.
  4. Faux : un site statique envoie les mêmes fichiers à tous, il ne connaît pas l'utilisateur.
  5. Faux : Laravel est un framework écrit en PHP, pas un langage.

Exercice 1.5 : tester ses variables

<?php
$nom = "Amal"; $age = 20; $taille = 1.68; $etudiant = true; $telephone = null;
Solution
  1. gettype : string, integer, double, boolean, NULL. get_debug_type : string, int, float, bool, null. Pour $taille, gettype dit « double » (nom historique), get_debug_type dit « float » (le nom utilisé dans le code).
  2. is_int($age) et is_float($taille) donnent true ; is_string($age) donne false.
  3. isset($telephone) donne false et is_null($telephone) donne true. isset est vrai seulement si la variable existe et n'est pas null : elle est déclarée mais vaut null.
  4. isset($email) donne false sans message. echo $email; donne « Warning: Undefined variable $email ».
  5. Après unset($age), isset($age) donne false.

Exercice 1.6 : prédire l'affichage

<?php
$a = "5"; $b = 3; $c = 'a vaut $a';
echo $a + $b; echo "<br>"; echo $a . $b; echo "<br>"; echo $c; echo "<br>"; var_dump($a * 2);
Solution
  1. $a + $b affiche 8 : + est l'addition, la chaîne numérique "5" est convertie en nombre.
  2. $a . $b affiche 53 : le point concatène deux chaînes.
  3. echo $c; affiche a vaut $a : entre guillemets simples il n'y a pas d'interpolation.
  4. var_dump($a * 2) affiche int(10).
  5. echo "7 jours" + 1; affiche 8 avec un Warning (« A non-numeric value encountered »). echo "semaine" + 1; provoque une TypeError « Unsupported operand types: string + int » et le script s'arrête.

Exercice 1.9 : le script saboté

<?php
$prenom = "Sara"; $age = 21; $prix = 12.5; $quantite = "3 articles";
const ECOLE = "EPA Agadir";
echo "Étudiante : " . $Prenom . "<br>";
echo 'Âge : $age ans<br>';
echo "École : " ECOLE . "<br>";
echo "Total : " . $prix * $quantite . " DH<br>";
echo "Remise : " . 10 + 5 . " %<br>";
echo "Fin de la fiche";
Solution
  1. Aucune ligne n'est affichée car c'est une Parse error : PHP lit tout le fichier avant d'exécuter quoi que ce soit, et une erreur de syntaxe empêche l'exécution complète. Il manque un point : "École : " . ECOLE.
  2. Anomalies après correction :
    • $Prenom devrait être $prenom : les noms sont sensibles à la casse, d'où le Warning « Undefined variable ».
    • 'Âge : $age ans' : guillemets simples, donc pas d'interpolation. Utiliser des guillemets doubles.
    • $quantite = "3 articles" : chaîne qui commence par un nombre, d'où le Warning « non-numeric value ». Déclarer $quantite = 3.
  3. Le total 37.5 est juste par hasard (12.5 × 3), mais il est obtenu avec un Warning : il ne faut pas s'y fier. Corriger la déclaration pour supprimer le Warning.
  4. « Remise : 15 % » s'affiche sans message car en PHP 8, + est évalué avant . : 10 + 5 vaut 15, puis la concaténation. Si PHP avait concaténé d'abord, on aurait calculé "Remise : 10" + 5 : chaîne non numérique, donc une TypeError. À retenir : mettez des parenthèses quand vous mélangez . et +.
  5. Arrêtent le script : la Parse error (rien ne s'exécute) et la TypeError. Laissent continuer : les Warnings (variable non définie, valeur non numérique).

Exercice 2.2 : tarifs d'un cinéma

Moins de 12 ans : 25 DH ; étudiant : 35 DH ; 60 ans et plus : 30 DH ; sinon 50 DH. Le mercredi, 20 % de réduction.

Solution
<?php
$age = 25; $etudiant = true; $jour = "mercredi";

// Ordre des tests : du plus restrictif au plus large
if ($age < 12)        { $prix = 25; }
elseif ($etudiant)    { $prix = 35; }
elseif ($age >= 60)   { $prix = 30; }
else                  { $prix = 50; }

// Réduction du mercredi avec le ternaire
$prix = ($jour === "mercredi") ? $prix * 0.8 : $prix;

// Même calcul de base avec match(true)
$base = match (true) { $age < 12 => 25, $etudiant => 35, $age >= 60 => 30, default => 50 };

echo "Prix à payer : $prix DH";   // Prix à payer : 28 DH

Pourquoi l'ordre compte : un enfant de 10 ans étudiant paie 25 DH. Si on testait $etudiant en premier, il paierait 35. Résultats vérifiés : 10 ans étudiant mercredi 20 DH ; 25 ans étudiant mercredi 28 DH ; 70 ans lundi 30 DH ; 30 ans mercredi 40 DH.

Exercice 2.3 : boucles

Solution
<?php
// 1. table de 7
for ($i = 1; $i <= 10; $i++) { echo "7 × $i = " . (7 * $i) . "<br>"; }

// 2. somme des pairs de 1 à 100
$somme = 0;
for ($i = 2; $i <= 100; $i += 2) { $somme += $i; }       // 2550

// 3. factorielle de 6 avec while
$f = 1; $i = 1;
while ($i <= 6) { $f *= $i; $i++; }                      // 720

// 4. FizzBuzz : tester 15 en premier
for ($i = 1; $i <= 30; $i++) {
    if ($i % 15 === 0)      { echo "FizzBuzz"; }
    elseif ($i % 3 === 0)   { echo "Fizz"; }
    elseif ($i % 5 === 0)   { echo "Buzz"; }
    else                    { echo $i; }
    echo "<br>";
}

// 6. codes HTTP
foreach ([200, 404, 301, 500, 403, 302, 418] as $code) {
    $msg = match ($code) {
        200 => "OK", 301, 302 => "Redirection", 403 => "Accès interdit",
        404 => "Page introuvable", 500 => "Erreur du serveur", default => "Code inconnu",
    };
    echo "$code : $msg<br>";
}

Question 5 : for ($i = 0; $i < 10; $i += 3) exécute le bloc 4 fois, avec $i = 0, 3, 6, 9. FizzBuzz : si on testait 3 avant 15, le nombre 15 afficherait « Fizz » seulement. Code 418 : « Code inconnu » grâce au default.

Exercice 3.2 : statistiques d'une promotion

$notes = ["Amine" => 14, "Sara" => 17.5, "Yassine" => 9, "Hiba" => 12, "Omar" => 17.5, "Rim" => 8];
Solution
<?php
// 1. somme avec array_reduce, effectif, moyenne
$somme = array_reduce($notes, fn($acc, $n) => $acc + $n, 0);   // 78
$moyenne = $somme / count($notes);                              // 78 / 6 = 13

// 2. admis : array_filter garde les clés (noms)
$admis = array_filter($notes, fn($n) => $n >= 10);
echo count($admis) . " admis sur " . count($notes) . " : " . implode(", ", array_keys($admis));
// 4 admis sur 6 : Amine, Sara, Hiba, Omar

// 3. écarts à la moyenne : array_map conserve aussi les clés
$ecarts = array_map(fn($n) => $n - $moyenne, $notes);
foreach ($ecarts as $nom => $e) { echo "$nom : " . sprintf('%+g', $e) . "<br>"; }
// Amine : +1, Sara : +4.5, Yassine : -4, Hiba : -1, Omar : +4.5, Rim : -5

sprintf('%+g', $e) affiche toujours le signe (+4.5, -5). Sans lui, les positifs n'auraient pas de « + ».

Exercice 4.1 : compter les visites

Solution
<?php

Question 3 : après fermeture puis réouverture du navigateur, c'est le compteur de session qui repart à 1. Le cookie de session (PHPSESSID) n'a pas de date d'expiration : il disparaît à la fermeture du navigateur, et le serveur ne retrouve plus les données. Le cookie du compteur a une durée d'une heure, il survit et le compteur continue.

Exercice 4.2 : hachage des mots de passe

Solution
<?php
$h1 = password_hash("secret123", PASSWORD_DEFAULT);
$h2 = password_hash("secret123", PASSWORD_DEFAULT);
var_dump($h1 === $h2);                         // false
var_dump(password_verify("secret123", $h1));   // true
var_dump(password_verify("Secret123", $h1));   // false (majuscule)
  1. Les deux empreintes sont différentes (60 caractères chacune) : un sel aléatoire est ajouté à chaque appel.
  2. password_verify donne true avec "secret123" et false avec "Secret123" : la casse compte.
  3. Le hachage est à sens unique : on ne peut pas retrouver le mot de passe. Avec « Mot de passe oublié », un site n'envoie donc jamais l'ancien mot de passe : il envoie un lien (avec un jeton temporaire) pour en choisir un nouveau.

function e(string $s): string { return htmlspecialchars($s, ENT_QUOTES, 'UTF-8'); }

$erreurs = [];

Exercice 5.3 : envoyer une photo

Solution (code testé)
<?php
$max = 1 * 1024 * 1024;                                    // 1 Mo
$autorises = ['image/jpeg' => 'jpg', 'image/png' => 'png'];   // JPG et PNG

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $f = $_FILES['photo'] ?? null;
    if (!$f || $f['error'] !== UPLOAD_ERR_OK)      { $message = "Erreur lors de l'envoi"; }
    elseif ($f['size'] > $max)                     { $message = "Fichier trop volumineux (1 Mo max)"; }
    else {
        $mime = (new finfo(FILEINFO_MIME_TYPE))->file($f['tmp_name']);   // type RÉEL
        if (!isset($autorises[$mime])) { $message = "Format refusé : JPG ou PNG"; }
        else {
            $nom = bin2hex(random_bytes(16)) . '.' . $autorises[$mime];
            move_uploaded_file($f['tmp_name'], __DIR__ . '/uploads/' . $nom);
            $image = 'uploads/' . $nom;                // affichée avec <img src="..." width="200">
        }
    }
}
// Formulaire : <form method="post" enctype="multipart/form-data"> <input type="file" name="photo">

Question 3 : un fichier texte renommé photo.jpg est refusé : finfo lit le contenu et trouve text/plain. Mais $_FILES['photo']['type'] contient image/jpeg, déduit par le navigateur du nom. Conclusion : le nom et le type fournis par le client se falsifient, seul le type réel lu dans le contenu est fiable.
