Partie A : prédire l'affichage (4 points, 0,5 par question)

Donnez exactement ce qu'affiche chaque extrait. Précisez le type quand c'est un var_dump.

A1

$a = "10"; $b = 5;
var_dump($a + $b, $a . $b);
Solution

int(15) puis string(3) "105". + additionne (la chaîne numérique est convertie), . concatène.

A2

$i = 5;
echo $i++ + ++$i;
Solution

Affiche 12. $i++ renvoie 5 puis $i vaut 6 ; ++$i passe à 7 et renvoie 7 ; 5 + 7 = 12.

A3

var_dump(0 == "a", "1" == "01", "10" == "1e1", 100 == "1e2");
Solution

false, true, true, true. En PHP 8, 0 == "a" est faux. Les trois autres comparent des chaînes numériques en nombres : à éviter, préférer ===.

A4

$t = [1, 2, 3];
$r = array_map(fn($x) => $x * 2, array_filter($t, fn($x) => $x > 1));
print_r($r);
Solution

Un tableau avec les clés conservées : [1] => 4 et [2] => 6. array_filter garde les clés 1 et 2, array_map les conserve.

A5

function f(int &$n) { $n++; }
$a = 1;
f($a); f($a);
echo $a;
Solution

Affiche 3 : le paramètre est passé par référence (&), chaque appel modifie $a.

A6

function compteur() { static $n = 0; return ++$n; }
echo compteur(), compteur(), compteur();
Solution

Affiche 123 : la variable static garde sa valeur d'un appel à l'autre.

A7

$x = null;
echo $x ?? "défaut";
echo isset($x) ? "oui" : "non";
echo empty("0") ? "vide" : "plein";
Solution

Affiche défautnonvide. ?? donne la valeur par défaut car $x est null ; isset(null) est faux ; "0" est vide.

A8

switch ("2") {
    case 2: echo "a";
    case 3: echo "b"; break;
    default: echo "c";
}
Solution

Affiche ab. switch compare en souple : "2" == 2. Sans break après le premier case, l'exécution « tombe » dans le suivant.

Partie B : tableaux et fonctions (6 points)

Les notes de la promotion

$etudiants = [
    ["nom" => "Amal",   "notes" => [12, 15, 9]],
    ["nom" => "Bilal",  "notes" => [8, 7, 10]],
    ["nom" => "Chaima", "notes" => [16, 14, 18]],
    ["nom" => "Driss",  "notes" => [10, 10, 10]],
];
  1. (1 point) Écrire une fonction typée moyenne(array $notes): float. Que renvoie-t-elle pour un tableau vide, et pourquoi ?
  2. (1 point) Ajouter à chaque étudiant la clé "moyenne" (arrondie à 2 décimales). Pourquoi foreach ($etudiants as $e) ne suffit-il pas ?
  3. (1,5 point) Avec array_filter, construire la liste des admis (moyenne d'au moins 10) et afficher « 3 admis : Amal, Chaima, Driss ».
  4. (1,5 point) Trier les étudiants par moyenne décroissante avec usort et afficher le classement.
  5. (1 point) Que se passe-t-il si on écrit $etudiants = usort($etudiants, ...); ?

Solution testée

<?php
$etudiants = [
    ["nom" => "Amal",   "notes" => [12, 15, 9]],
    ["nom" => "Bilal",  "notes" => [8, 7, 10]],
    ["nom" => "Chaima", "notes" => [16, 14, 18]],
    ["nom" => "Driss",  "notes" => [10, 10, 10]],
];

// 1. moyenne d'un tableau de notes (0 si le tableau est vide : pas de division par zéro)
function moyenne(array $notes): float
{
    return count($notes) === 0 ? 0 : array_sum($notes) / count($notes);
}

// 2. ajouter la clé "moyenne" : on passe par la clé $i, car $e est une copie
foreach ($etudiants as $i => $e) {
    $etudiants[$i]["moyenne"] = round(moyenne($e["notes"]), 2);
}

// 3. les admis (moyenne d'au moins 10)
$admis = array_filter($etudiants, fn($e) => $e["moyenne"] >= 10);
echo count($admis) . " admis : " . implode(", ", array_column($admis, "nom")) . "\n";
// 3 admis : Amal, Chaima, Driss

// 4. classement par moyenne décroissante
usort($etudiants, fn($a, $b) => $b["moyenne"] <=> $a["moyenne"]);
foreach ($etudiants as $rang => $e) {
    echo ($rang + 1) . ". {$e['nom']} : {$e['moyenne']}\n";
}
// 1. Chaima : 16 | 2. Amal : 12 | 3. Driss : 10 | 4. Bilal : 8.33
  1. La fonction renvoie 0 pour un tableau vide : sans cette protection, array_sum / count diviserait par zéro (erreur DivisionByZeroError).
  2. Dans foreach ($etudiants as $e), $e est une copie de l'élément : modifier $e['moyenne'] ne change pas $etudiants. Il faut la clé : foreach ($etudiants as $i => $e) puis $etudiants[$i]['moyenne'] = ....
  3. array_filter garde les clés d'origine (0, 2, 3) : array_column($admis, "nom") les ignore, ce qui donne la liste voulue.
  4. Classement : Chaima 16, Amal 12, Driss 10, Bilal 8.33.
  5. usort modifie le tableau par référence et renvoie true : $etudiants deviendrait true, le tableau serait perdu.

Partie C : formulaire de contact (6 points)

  5. (1 point) Afficher « Merci Sara, votre message a été envoyé. » une seule fois, et empêcher le double envoi au rechargement.
Solution détaillée

contact.php (testé)

<?php
session_start();

function e(string $s): string { return htmlspecialchars($s, ENT_QUOTES, 'UTF-8'); }

$erreurs = [];
$d = ['nom' => '', 'email' => '', 'message' => ''];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // 1. recevoir et nettoyer
    $d['nom']     = trim($_POST['nom'] ?? '');
    $d['email']   = trim($_POST['email'] ?? '');
    $d['message'] = trim($_POST['message'] ?? '');

    // 2. valider côté serveur
    if ($d['nom'] === '') {
        $erreurs['nom'] = "Le nom est obligatoire.";
    }
    if (!filter_var($d['email'], FILTER_VALIDATE_EMAIL)) {
        $erreurs['email'] = "Adresse email invalide.";
    }
    if (strlen($d['message']) < 10) {
        $erreurs['message'] = "Le message doit contenir au moins 10 caractères.";
    }

    // 3. enregistrer dans un CSV (mode a : ajout), puis PRG avec message flash
    if (empty($erreurs)) {
        if (!is_dir(__DIR__ . '/data')) { mkdir(__DIR__ . '/data', 0755, true); }
        $f = fopen(__DIR__ . '/data/messages.csv', 'a');
        if ($f === false) {
            exit("Service indisponible.");
        }
        fputcsv($f, [date('Y-m-d H:i:s'), $d['nom'], $d['email'], $d['message']], escape: '');
        fclose($f);

        $_SESSION['flash'] = "Merci " . $d['nom'] . ", votre message a été envoyé.";
        header('Location: merci.php');
        exit;
    }
}
?>

Partie D : questions de cours (4 points, 1 par question)

  1. Quelle est la différence entre include et require ? Pourquoi utilise-t-on require_once pour un fichier de fonctions ?
  2. Citez trois différences entre un cookie et une session.
  3. Pourquoi ne faut-il pas stocker un mot de passe avec md5 ? Quelles fonctions PHP utiliser ?
  4. Expliquez le motif Post / Redirect / Get et le rôle du message flash.
Solution
  1. Fichier introuvable : include émet un Warning et le script continue ; require provoque une erreur fatale et le script s'arrête. Avec _once, le fichier n'est chargé qu'une fois, même si l'instruction est rencontrée plusieurs fois : indispensable pour un fichier de fonctions, car déclarer deux fois la même fonction provoque une erreur.
  2. Le cookie est stocké chez le client, la session sur le serveur. Le cookie est lisible et modifiable par l'utilisateur, la session non (seul l'identifiant circule). Le cookie peut survivre à la fermeture du navigateur, la session expire après inactivité ou déconnexion. Autres : taille (environ 4 Ko contre pratiquement illimitée), usage (préférences contre authentification).
  3. MD5 est très rapide, donc facile à attaquer par essais successifs, et sans sel il donne la même empreinte pour le même mot de passe. On utilise password_hash($mdp, PASSWORD_DEFAULT) (bcrypt, sel automatique, volontairement lent) et password_verify($saisi, $empreinte).
  4. Après un POST réussi, on ne renvoie pas la page de résultat : on redirige (302) vers une page lue en GET, avec header('Location: ...'); exit;. Recharger cette page ne renvoie plus le formulaire, donc pas de doublon. Les variables du script précédent ont disparu : le message flash, stocké en session avant la redirection, est affiché une seule fois par la page suivante, puis supprimé.
