Quatre approches : natif (un code par OS, performance maximale, coût élevé), hybride (code web dans un conteneur : HTML, CSS, JavaScript avec Ionic et Capacitor), multiplateforme native (un seul code : Flutter, React Native, .NET MAUI), application web progressive. Flutter et Dart Priorité 2

Définition : Flutter

Framework open source de Google pour créer des applications Android, iOS, Web et Desktop à partir d'un seul code, écrit en Dart. Première version stable : Flutter 1.0, décembre 2018. Dart date de 2011.

  • Avantages : une base de code pour toutes les plateformes ; bonnes performances (le code Dart est compilé en code natif, compilation AOT) ; pas de WebView ; interface très personnalisable grâce aux widgets ; hot reload ; écosystème de packages.
  • Dart : langage orienté objet, typage statique. Deux modes de compilation : JIT (Just In Time, pendant le développement, ce qui permet le hot reload) et AOT (Ahead Of Time, pour l'application finale).
  • Outils : Android Studio, Visual Studio Code, Flutter DevTools (analyse des performances, débogage).
  • Tout est un widget : les boutons comme les mises en page.

Dart : les bases Priorité 1

  • main() est le point d'entrée : la première fonction appelée. Commentaires : //, /* ... */ et /// pour la documentation.
  • Variables sensibles à la casse. Trois façons de déclarer : type explicite (int age = 25;), var (le type est déduit puis fixé), dynamic (le type peut changer).
  • final : affectée une seule fois, valeur connue à l'exécution. const : constante connue à la compilation.
  • Types : String, bool, int, double, num (int ou double), List, Set, Map.
  • Interpolation : $variable pour une variable, ${expression} pour une expression. "$numbers[0]" n'affiche pas l'élément : écrire "${numbers[0]}".
  • Conversions : toInt() (supprime la partie décimale), toDouble(), toString(), toList(), toSet() (sans doublons). Lire un nombre saisi : int.parse(...), double.parse(...).
  • Affichage : print() (avec retour à la ligne), stdout.write() (sans). Lecture : stdin.readLineSync().
int age = 25;
var ville = 'Agadir';          // le type String est déduit
dynamic x = 5;
x = 'cinq';                    // dynamic accepte un changement de type
final nom = 'Sara';            // une seule affectation
const pi = 3.14;               // constante connue à la compilation
print('$nom a $age ans, ville $ville, x = $x, pi = $pi');
print('Dans 5 ans : ${age + 5} ans');

Null safety : éviter les erreurs de valeur nulle Priorité 1

Depuis Dart 2.12, les types ne peuvent pas contenir null par défaut. On l'autorise avec ? (String? nom).

ÉcritureSens
String?type nullable : peut valoir null (et vaut null par défaut)
nom?.lengthappelle seulement si nom n'est pas null, sinon donne null
nom ?? 'inconnu'valeur par défaut si nom est null
nom!« je suis sûr que ce n'est pas null » (plante sinon)
late String m;initialisée plus tard, mais avant son utilisation
String? prenom;                // le ? autorise null
print(prenom?.length);         // ?. : pas d'erreur, donne null
print(prenom ?? 'inconnu');    // ?? : valeur par défaut
prenom = 'Ali';
print(prenom!.length);         // ! : je suis sûr qu'il n'est pas null
late String message;           // initialisée plus tard, jamais null
message = 'prêt';
print(message);

Opérateurs, conditions et boucles Priorité 1

  • Opérateurs arithmétiques + - * / ~/ %, comparaison == != < > <= >=, logiques && || !, ternaire condition ? a : b, ??.
  • Conditions : if, if ... else, if ... else if ... else, switch/case.
  • Boucles : for, for ... in (parcourt une collection sans compteur ; pour une Map, utiliser .entries, .keys ou .values), while, do ... while. break quitte la boucle, continue passe à l'itération suivante.
final prix = [10, 20, 30];
var total = 0;
for (var i = 0; i < prix.length; i++) {
  if (prix[i] == 20) continue;       // continue : passe au suivant
  total += prix[i];
}
for (final p in prix) {
  if (p > 25) break;                 // break : quitte la boucle
  print('prix : $p');
}
print('total : $total');
var statut = total > 30 ? 'cher' : 'abordable';   // opérateur ternaire
print(statut);

Les fonctions Priorité 1

  • Une fonction a des paramètres (entrées) et un résultat (retour). Dart n'a pas de surcharge : deux fonctions ne peuvent pas porter le même nom.
  • Syntaxe arrow => quand le corps n'a qu'une instruction (le return disparaît).
  • Paramètres : obligatoires (dans l'ordre), optionnels positionnels entre crochets [ ], optionnels nommés entre accolades { } (obligatoires seulement avec required, valeur par défaut possible).
  • Fonction lambda (anonyme) : sans nom, passée en paramètre, par exemple à map.
int carre(int n) => n * n;                                   // syntaxe arrow
void saluer({required String nom, int age = 18, String? ville}) {
  print('Nom : $nom, age : $age, ville : $ville');           // paramètres nommés
}
String joindre(String a, [String? b]) => b == null ? a : '$a $b';   // optionnel positionnel
print(carre(4));
saluer(nom: 'Ali');
saluer(age: 25, nom: 'Sara', ville: 'Agadir');
print(joindre('Bonjour'));
print(joindre('Bonjour', 'Sara'));
final doubler = (int n) => n * 2;                            // fonction lambda
print([1, 2, 3].map(doubler).toList());

Programmation orientée objet Priorité 1

  • Une classe est un modèle avec des propriétés et des méthodes. Le constructeur porte le nom de la classe et n'a pas de type de retour ; this.nom initialise directement l'attribut. Le mot new est facultatif.
  • Constructeur nommé : Etudiant.sansAge(...), à la place de la surcharge.
  • Getter (sans paramètre, renvoie une valeur) et setter (un paramètre, ne renvoie rien).
  • Héritage : extends. Classe abstraite : abstract, non instanciable, ses méthodes abstraites n'ont pas de corps. Interface : implements oblige à fournir tous les membres, même ceux déjà implémentés ; une classe peut implémenter plusieurs interfaces.
  • Polymorphisme : une même méthode produit un comportement différent selon l'objet.
  • Bibliothèques : import 'dart:math'; (dart:core est automatique, dart:io pour le clavier et les fichiers, dart:convert, dart:async).
class Etudiant {
  String nom;
  int age;

  Etudiant(this.nom, this.age);                       // constructeur
  Etudiant.sansAge(this.nom) : age = 18;              // constructeur nommé

  String get description => '$nom, $age ans';         // getter
}

class Etudiant2 extends Etudiant {                    // héritage
  String filiere;
  Etudiant2(super.nom, super.age, this.filiere);

  @override
  String get description => '${super.description}, $filiere';
}
abstract class Animal {
  void parler();                                      // méthode abstraite
  void manger() => print("L'animal mange");
}

class Chien extends Animal {
  @override
  void parler() => print('Wouf Wouf');
}
final e1 = Etudiant('Ali', 22);
final e2 = Etudiant.sansAge('Sara');
final e3 = Etudiant2('Omar', 21, 'GI');
print(e1.description);   // Ali, 22 ans
print(e2.description);   // Sara, 18 ans
print(e3.description);   // Omar, 21 ans, GI

Chapitre 2 : les widgets

Qu'est-ce qu'un widget ? Priorité 1

Définition : widget

Un widget est un objet immuable qui décrit une partie de l'interface. L'interface est écrite en code Dart (pas en XML). Les widgets s'imbriquent : une Column peut contenir des Row, qui contiennent des Image.

Structure d'un projet et démarrage Priorité 2

  • lib/ : le code Dart (main.dart contient main()). pubspec.yaml : nom, dépendances, images, polices. test/ : tests. build/ : fichiers générés. android, ios, web... : fichiers propres à chaque système.
  • main() est obligatoire et s'écrit exactement ainsi. runApp(widget) attache le widget racine à l'écran : sans lui, rien ne s'affiche.
  • Pour l'APK : Build, Flutter, Build APK. Le fichier est dans build/app/outputs/flutter-apk/app-release.apk.

child ou children ?

Un widget qui a un seul enfant (Container, Center, Padding, Card, SafeArea) utilise child. Un widget qui en a plusieurs (Column, Row) utilise children: [ ... ].

Stateless et Stateful Priorité 1

  • StatelessWidget : ne change jamais après sa création (texte fixe, icône). Une classe avec build().
  • StatefulWidget : peut changer quand l'utilisateur interagit. Deux classes : le widget (avec createState()) et la classe d'état qui extends State<...> et contient build(). Le préfixe _ rend la classe privée au fichier.
  • L'état est l'ensemble des données qui peuvent changer et qui influencent l'affichage (un compteur, une case cochée). On le modifie dans setState(() { ... }) : Flutter reconstruit alors l'interface.
class _MonAppState extends State<MonApp> {
  int compteur = 0;

  @override
  Widget build(BuildContext context) {
    return FloatingActionButton(
      onPressed: () {
        setState(() {       // sans setState, l'écran ne change pas
          compteur++;
        });
      },
      child: Text('$compteur'),
    );
  }
}

Hot reload, hot restart, run Priorité 2

Le hot reload injecte le code modifié et garde l'état ; le hot restart redémarre l'application et réinitialise l'état ; run lance tout depuis le début. Tableau comparatif sur la page Widgets en images.

Les champs de texte Priorité 1

  • TextField : champ de saisie. TextFormField : même chose, dans un Form, avec validator.
  • InputDecoration : labelText, hintText, icon, prefixIcon, border: OutlineInputBorder().
  • Propriétés : maxLines (plusieurs lignes), keyboardType (clavier adapté), obscureText (mot de passe), obscuringCharacter, maxLength.
  • Lire la saisie : soit onChanged: (val) { ... }, soit un TextEditingController relié par controller: puis controller.text.
  • Valider : Form(key: _formKey) avec GlobalKey<FormState> ; chaque validator renvoie un message d'erreur ou null ; _formKey.currentState!.validate() renvoie true si tout est valide.
TextFormField(
  validator: (val) {
    if (val!.isEmpty) return 'prière de saisir une valeur';
    return null;                     // null = la valeur est correcte
  },
)

ElevatedButton(
  onPressed: () {
    if (_numberForm.currentState!.validate()) {
      setState(() { message = 'Formulaire validé'; });
    } else {
      setState(() { message = 'Prière de fixer les erreurs'; });
    }
  },
  child: const Text('Valider'),
)
